# Testing checklist

## Before upload

- [ ] `php -l` every PHP source file using PHP 8+ CLI.
- [ ] Import `database/schema.sql` into an empty disposable MySQL database and confirm all foreign keys/indexes are created.
- [ ] Set the DB password privately in `config/database.php` and the exact CORS origin in `config/app.php`; confirm files under `config` and `database` are outside the document root.
- [ ] Create test users with `password_hash()` in a disposable database.
- [ ] Run the frontend build and configure only a local/staging API URL.

## HTTP checks (use a disposable test system)

- [ ] `GET /api/v1/health` -> 200 without credentials when `SELECT 1` succeeds; response contains no DB details. With DB unavailable, expect generic 500 JSON.
- [ ] `GET /api/v1/auth/me` -> 401 without session.
- [ ] Login with a wrong password -> 401; valid login -> 200 and session cookie.
- [ ] `/auth/me` returns server role, account status, permissions, and default route; login with inactive user -> 401.
- [ ] Submit `/auth/register` with valid details -> generic 202; confirm no user exists until an administrator approves.
- [ ] Invalid registration input -> 422; duplicate account or pending request gets the same generic 202 and creates no duplicate pending row.
- [ ] Administrator lists pending requests, approves one with an assigned role -> one active user is created; reject another -> no user is created. Confirm non-admin access -> 403 and a request cannot be reviewed twice.
- [ ] Staff `/users` -> 403; staff `/directory` returns only operational references; admin user profile/role/status changes succeed and unauthorized role changes -> 403.
- [ ] Final active administrator cannot be deactivated or demoted; administrators cannot change their own role/status.
- [ ] Password change requires the current password and a 12+ character new password.
- [ ] `GET /auth/me` after login -> 200 safe profile; logout -> 200 with an expired session cookie; subsequent `/auth/me` -> 401.
- [ ] `GET /shifts`, `/handovers`, `/tasks`, `/incidents` with session -> 200; nonexistent details -> 404.
- [ ] Create handover with missing/short summary -> 422; assigned outgoing staff can create draft; unrelated staff -> 403.
- [ ] Submit draft -> 200 and notification/audit rows created; repeat submit -> 409.
- [ ] Incoming assigned staff can acknowledge submitted handover; unrelated staff -> 403; repeat/invalid transition -> 409.
- [ ] Task/incident invalid enum -> 422; unauthorized task mutation or incident status change -> 403.
- [ ] Carry task to a different shift as admin/supervisor; same task ID moves shifts once, old handover links remain, and one event notification/audit entry is created. Repeating carry should not duplicate the task.
- [ ] Users cannot list or mark another user's notifications; attempted foreign notification ID -> 404.
- [ ] Database unavailable -> generic 500 JSON; inspect private server logs for diagnosis and verify no SQL/credentials in response.
- [ ] Requests from unapproved origins receive no allow-origin response; approved exact origin gets credentials-enabled CORS.
- [ ] Verify notifications are generated by the handover, incident, and critical-task event flows, not by a sample endpoint.

Do not run these against a live database during setup.

## Windows local API workflow smoke test

`tests/smoke-api.ps1` runs only against `http://127.0.0.1` or `http://localhost`; it refuses other hosts and sends the exact local CORS `Origin`. It does not create a database, import SQL, or clean up rows. Run it only after preparing a disposable database and three disposable accounts with roles `ADMINISTRATOR`, `OUTGOING_STAFF`, and `INCOMING_STAFF`. The database needs an outgoing-to-incoming shift plus a second destination shift. The script creates account, task, incident, handover, notification, and audit test rows, including a rollback probe.

From the repository root, after configuring `backend/config/database.php` for the isolated local database and adding those fixtures:

```powershell
php -S 127.0.0.1:8000 -t backend/public backend/dev-router.php
```

In a second PowerShell window:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File backend/tests/smoke-api.ps1
```

The script securely prompts for each test account's password and prints PASS/FAIL results. It leaves created rows in the disposable database so the results can be inspected; drop that database when finished. To run PHP syntax checks from the repository root:

```powershell
Get-ChildItem backend -Recurse -Filter *.php | ForEach-Object { php -l $_.FullName }
php -m | Select-String -Pattern 'PDO|pdo_mysql'
```

At the latest environment check, PHP was absent from PATH and common install locations. A `MySQL80` Windows service and MySQL 8.0 client were found, but the service refused a read-only TCP connection to `127.0.0.1:3306`; no local API or database tests have run. Configure/enable a local test listener and use credentials for a dedicated test database before running the script. Never point it at the production host.
